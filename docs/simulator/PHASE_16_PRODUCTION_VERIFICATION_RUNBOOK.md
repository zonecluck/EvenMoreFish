# EvenMoreFish Simulator — Phase 16 Production Verification Runbook

> **STATUS: BLOCKED / STAGING ONLY.** This source has not passed a full Gradle build, actual Paper runtime, client packet rendering, or the G3/G5/G7/G15 gates. Phase 16 adds packet cleanup fixes, deterministic fault-injection tests, CI compilation workflow and a fail-closed evidence ledger; it does not lift admin-only limits.

## 1. Release boundaries

- Never enable Simulator globally on production just because this document exists.
- All new `simulator.yml`/visual feature toggles remain OFF by default.
- Keep EMF's existing `config.yml` `version` migration key; do not reset it to `config-version`.
- Keep EMF's original fish item, event, rarity, bait, rod, shop and competition contracts intact.
- PacketEvents must be installed separately on the **Paper 1.21** variant; do not shade it or install two conflicting EMF jars.
- **Folia is not claimed.** This module assumes a single Paper owner thread.
- Public rollout is **not implemented**: existing session takeover/AI/reward code is admin-only even after setting `paper-gates-verified: true`.

## 2. Reproduce the full build and automated tests

Run from the repository root on a networked host with JDK 21 and the repositories configured in the project:

```bash
bash qa/run-phase16-validation.sh | tee qa/evidence/headless-regression.log
bash ./gradlew :even-more-fish-plugin:test :even-more-fish-plugin-1-21:shadowJar \
  --no-daemon --stacktrace 2>&1 | tee qa/evidence/gradle-compile-test.log
```

The last command is a **real compile + JUnit + Paper 1.21 variant JAR** gate. CI template: `.github/workflows/phase16-staging-build.yml`. If Gradle cannot download dependencies, the gate is **BLOCKED**, not PASS. Keep the complete failure log and resolve it before testing.

Do not install a source ZIP in `plugins/`. Install only a JAR generated by a successful Gradle build for the matching Paper variant.

## 3. Stage on an isolated Paper server

1. Record the **exact Paper build**, Java version, PacketEvents version, and loaded hooks (WorldGuard/RedProtect/Vault/PlaceholderAPI, etc.).
2. Back up the existing production EMF JAR, `plugins/EvenMoreFish` config/data, and database if one is in use. Use a separate staging copy; never test destructive migration on live data.
3. Verify legacy fishing **before** enabling any Simulator toggle: bait, custom rods, rare fish, shop, journal, competition and native treasure all behave as before.
4. Define a dedicated staging `WORLD` or `CUBOID` zone, initially disabled. Check deny/priority/region-provider rules before enabling it. Keep ordinary players away.
5. Enable **only** `simulator.enabled`, the dedicated zone and admin-only preview in a controlled session, never public reward by default.
6. Grant `emf.admin.simulator.preview` and `emf.admin.simulator.probe` to testing staff only. Remove these permissions from unrelated staff accounts.
7. Ensure `reward-bridge.enabled: false` and `reward-bridge.paper-gates-verified: false` through G3 and G5.
8. Use `/emf admin simulator status`, `doctor`, `trace` and the Phase 15 model diagnostics; save server logs and client recordings.

### G3 — Native hook control (manual PASS required)

- Inside the zone, wait for bobber to settle, then run diagnostic native hook probe.
- Confirm **no vanilla bait/loot/EXP** appears from an owned probe. Test `BITE`, `CAUGHT_FISH`, `REEL_IN`, disconnect/teleport/reload, cancelled events and an offhand rod.
- Test outside the zone, overlapping deny zone, denied WorldGuard/RedProtect region and missing region provider; the legacy engine must not be silently bypassed.
- Test cancellation by another plugin at several `PlayerFishEvent` priorities.
- An unexpected native bite or a doubled item/EXP = **FAIL**. Record event trace and exact Paper build.

### G5 — Real client packet fish (manual PASS required)

- One viewer and two viewers: shared/private fish, dynamic movement, yaw, spawn and despawn.
- Test water/chunk unload, world change, fishing-zone exit, packet send error, client reconnect and `/emf admin simulator off`.
- Test restart/reload and one simulated PacketEvents failure. Ensure no ghost fish after cleanup grace/reconnect.
- Check Minecraft client's entity list and packet errors; headless synthetic transport tests cannot prove this behavior.

### G7 — Catch and reward consistency (manual PASS required)

- **Only after G3/G5** consider enabling the admin-only reward bridge, and only in an isolated test world.
- Note: EMF's bait-loot/native treasure defaults can force the legacy path. Document any *staging-only* overrides required to exercise the bridge. Restore normal rules afterwards.
- Verify `FishKey`, rarity, size, item metadata, lore, rod and bait hooks, `EMFFishCaughtEvent` cancellation, double reel, competition, statistics and persistent database events.
- Inventory-full, inventory-write ambiguity, item-drop failure, quit/relog during commit and plugin disable must not yield duplicate rewards. A single uncertain reward outcome requires manual reconciliation, **not automatic retry**.
- A cinematic failure must never retry or grant a second item.

### G15 — Resource-pack custom models (manual PASS required)

- Test one player with successfully loaded matching pack ID and another who declined; **same fish** must appear as `ItemDisplay` for the first and vanilla fish for the second.
- Verify actual texture, scale, rotation, interpolation, daylight/water depth and Legendary cinematic orientation.
- Test wrong pack ID, pack load failure, version mismatch and hot pack switch; no invisible model or leaked private fish.
- Do not treat a model identifier in `models.yml` as proof of client asset availability.

### Real-load, shutdown and rollback (manual PASS required)

- Profile **1, 10, 30, 50, 100** concurrent anglers if the staging hardware can support them. Record TPS, MSPT p50/p95/p99, packet sends, heap/GC, viewer count, spawn/cleanup backlog, and physical server specs. The mock benchmarks are not evidence.
- Restart/reload during active school, cinematic and catch; test client disconnect when cleanup queue contains IDs.
- Deliberately break PacketEvents on staging: the system must fail closed and not keep allocating client virtual entities.
- Verify old EMF vanilla catches function when the Simulator is OFF.
- Test rollback by disabling the new JAR, restoring the backed-up version/config and confirming stored fish still work. Do not run two EMF versions simultaneously.

## 4. Release evidence protocol

`qa/evidence/PHASE16_RELEASE_EVIDENCE.json` ships with every field `PENDING`. For each actual test:

1. Store a nonempty log/recording transcript in `qa/evidence/`.
2. Record the SHA-256 (e.g., `sha256sum qa/evidence/G5_PACKET_CLIENT.log`).
3. Set that field's `status` to `PASS`, `log` to the project-relative path, and `sha256` to its actual digest **only when a human verified the test**.
4. Fill reviewer, date and exact server build. `python3 qa/phase16_release_gate.py` will remain exit code 2 while anything is missing.

Even if the script says evidence attachments are complete, an owner must still review logs/video and separately approve the public-mode architecture. The tool only checks evidence integrity, not semantic correctness of Minecraft gameplay. Never set `paper-gates-verified` from this script.

## 5. Emergency rollback

1. Use `/emf admin simulator off`, if available; otherwise stop the staging server. **Never hot-swap the JAR file.**
2. Confirm all sessions/packet retries are stopped; ask affected clients to disconnect/reconnect if PacketEvents was unavailable.
3. Restore the previous EMF JAR and backed-up config/data appropriate to that build. Keep a copy of failing logs before restart.
4. Verify `/emf` and baseline vanilla catch, item metadata, shop, competition and database stats. Report any discrepancies before returning players to the zone.
